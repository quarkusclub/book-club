The problem

Which phone number failed?

Logs · error messages · debugging

A useful representation makes state quick to inspect.

toString is one of the most useful methods for debugging. A Failed to connect to message followed by an object should help identify the number in use. We will compare the same logical state through small examples.
The inherited implementation

ClassName@hexHash

Class name + hexadecimal hash.
Little information about the phone's value.

It is not a description of the fields.

Object.toString uses getClass().getName(), @ and Integer.toHexString(hashCode()). Do not describe this as necessarily a memory address or identity hash: this class already overrides hashCode. The text still does not describe its three fields. Source: https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Object.html#toString() .

Zeros are part of the format

3, 14, 123 → 003-014-0123

Fixed widths: three, three and four digits.

The zero in the format specifier requests leading-zero padding. The constructor rejects negatives and values exceeding the accepted widths, preventing invalid numbers from lengthening the representation. Zero is allowed in this teaching example. We are not validating real telephone numbering rules.

IMPLICIT USE

You already call toString

String concatenation · println(Object) · %s

These operations do not require explicitly writing object.toString(). String concatenation uses the representation, as does println(Object). For this example, which does not implement Formattable, String.format and printf with %s use toString. Do not generalize to %d or every format conversion.

A public decision

A specified format becomes a commitment

If documentation promises “XXX-YYY-ZZZZ”,
consumers may depend on that format.

Changing it later can break clients.

Documenting an exact format is an API choice. Programmers may use it in files, messages or conversions, so later changes can break them. Specified formats are not prohibited; this is the consequence of choosing one. PhoneNumber's documentation accepts that commitment.
The contract is in the documentation
format/PhoneNumber.java
Javadoc is necessary here: format, widths and padding form a public contract not apparent from the method name. The promise is intentional.

This is the notes' central distinction. PhoneNumber promises its format. Potion explicitly leaves exact details unspecified and subject to change while giving a typical example. This preserves room to evolve its representation while keeping relevant information for humans.

PROGRAMMATIC ACCESS

State without parsing

If data matters to code, provide an accessor.

Do not force clients to call toString and then substring to recover an area code. The larger problems are format coupling, fragility and difficulty evolving the representation. Parsing cost can be secondary, but is not the main argument. Even with a specified format, accessors provide a direct typed API.
Accessors for numeric values
format/PhoneNumber.java
Accessors expose shorts, not substrings of the representation. lineNumber remains the numeric value 533; the extra zero belongs only to the text.

TOOLS HELP

Generated and useful

Evaluate whether the representation fits the object's meaning.

Do not say generated toString is always inappropriate. IDEs, AutoValue and records can produce implementations much better than Object.toString. Ask whether listing fields is the best representation of this object. For a phone number, the natural format may be better.

Recap

Item 12

  • Concise text with relevant information
  • Concatenation, println and %s use the representation
  • A specified format is a public promise
  • Provide state access without parsing
  • Evaluate the meaning of generated text
The recommendation is to override toString in instantiable classes with a useful textual representation, especially value objects and objects often observed in logs or debugging. Do not turn it into a literal obligation for every instantiable class or ignore an adequate inherited representation.
